# Changelog

All notable changes are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Unreleased changes accumulate under `## [Unreleased]` until a tag is cut.

## [Unreleased]

### Added

- `--xref <SYMBOL>` finds every call site that targets the given
  function name or hex address, grouped by containing caller. Scanner 1
  resolves direct `CALL rel32` sites; Scanner 2 adds direct
  `CALL [rip+itab+slot]` indirect dispatch sites for any interface-
  method implementation, carrying the resolved itab address and
  interface method name inline. amd64 only. (`b1ac556`, `f87da96`)

## [1.2.0] - 2026-06-23

### Added

- `--data-at <ADDR>` inspects bytes at a data address through every
  recovery map the binary has: function table, itab table, section
  map. Six interpretation modes: `bytes`, `qwords`, `ptrs` (qwords +
  symbolize each value), `ifaces` (16-byte Go iface header resolved
  through itab table, with the dispatched method body address inline),
  `slice-header` (24-byte slice header, symbolized), `string` (16-byte
  Go string header with quoted preview). `--data-count N` reads N
  records instead of N bytes for structured modes.
- `--xref-readers <ADDR>` and `--xref-writers <ADDR>` scan `.text` for
  RIP-relative instructions touching a data address. Five-kind
  taxonomy: `lea`, `mov-load`, `mov-store`, `cmp`, `call-indirect`.
- `--strings` walks read-only sections for printable runs with
  `--strings-min` and substring filter.
- `--info` prints a section map with `(ptr|noptr, ro|rw)` classification
  for every Go-relevant section.
- `--show value|pointer|both` filter hides Go's autogenerated
  pointer-receiver method thunks (or shows only thunks). Applies to the
  function listing, `--itabs` concrete column, and `--xrefs`. Itab-
  dispatched pointer thunks stay visible under `--show value` with an
  `(itab thunk)` marker.
- `--itabs` annotates each row with `(reachable)` or `(unreachable)`
  based on whether the itab address is referenced from `.text` or any
  data section. Suppress with `--no-itab-reachability`.
- `--buildinfo` synthesizes a fallback record from the pclntab magic
  byte when the modinfo blob is stripped. The synthesized `go_version`
  encodes the inference inline (`~1.20+ (inferred ...; modinfo wiped)`)
  so downstream consumers cannot mistake the guess for ground truth.

### Changed

- `--info` and `--detect-garble` now share one unified verdict. The
  two heuristics previously contradicted each other on the same input
  (one would call it garbled, the other would not). `--detect-garble`
  also defines exit-code semantics: `0` garbled, `1` clean, `2`
  indeterminate.
- `--itabs --filter` matches against interface-method names in addition
  to interface and concrete names. On garble-default binaries where
  type columns are hashed, the method column is the only signal.
- `--xrefs` text output is indented by depth-from-root. Truncation
  footer now lands on stdout (same stream as the graph) so piping
  through `less` does not hide it.

## [1.1.0] - 2026-05-30

### Added

- `unstrip::inline::inline_callgraph` reconstructs the inlined-call
  graph from a stripped Go binary's `FUNCDATA_InlTree`. Witnessed
  format-stable across Go 1.22 through 1.24. Anonymous-inline nodes
  preserved as first-class structural recoveries when callee names
  have been stripped (garble `-tiny`, `-ldflags=-s -w`).
